# Сравнение BFS: классический подход и GraphBLAS

Данный проект посвящен сравнительному анализу производительности двух принципиально разных подходов к обходу графа в ширину (BFS) с построением дерева предков (parent-BFS): 
1. **Классический последовательный алгоритм**.
2. **Матричный алгоритм** с использованием библиотеки линейной алгебры `SuiteSparse:GraphBLAS`.

В качестве эталона для проверки корректности и базовой скорости используется библиотека **Boost Graph Library (BGL)**.

## Реализация подходов

Оба подхода реализованы на языке C и используют формат CSR (Compressed Sparse Row) для начального представления графа. В классическом алгоритме работа идет напрямую с массивами row_ptr и col_idx, а в GraphBLAS матрица импортируется в библиотеку с помощью функции GxB_Matrix_import_CSR. Сравнение происходит по parent-версиям (с сохранением дерева предков) этих обходов.

*   **Classic BFS:** Реализован строго последовательный обход через очередь на базе массива FIFO (первый пришёл - первый ушёл). Используется одно ядро CPU.
*   **GraphBLAS BFS:** Реализован алгебраический подход. Шаг обхода выполняется через операцию умножения вектора фронта на матрицу (`GrB_vxm`) с использованием булева полукольца `LOR-LAND` (Logical OR over Logical AND). Библиотека автоматически распараллеливает эту операцию по всем ядрам CPU.

## Структура проекта

*   `src/tests/` — модульные тесты (C и C++).

## Экспериментальный стенд и выборка графов

Для обеспечения воспроизводимости и чистоты замеров эксперименты проводились на строго фиксированном стенде со следующими характеристиками:
*   **Процессор:** Intel(R) Core(TM) Ultra 7 255H (16 ядер/потоков).
*   **Операционная система:** Linux (Ubuntu).
*   **Компилятор:** GCC с флагом оптимизации `-O3`.

**Методика замеров:**
Перед каждым запуском частота процессора жестко фиксировалась на максимальном значении с помощью утилиты `cpupower frequency-set -g performance` (Performance Governor). Это необходимо для исключения ошибок, связанных с троттлингом (снижением частоты из-за нагрева) и работой технологии Turbo Boost. Каждый замер времени выполнения (в микросекундах) усреднялся по 10 независимым запускам.

**Выборка данных (54 графа):**
Исследование проводилось на выборке из **54 графов**, которые делятся на две категории:
1.  **Реальные графы** из открытой коллекции University of Florida Sparse Matrix Collection (SuiteSparse), включая `com-Orkut`, `roadNet-CA`, `wiki-Talk`, `cit-Patents` и другие.
2.  **Синтетические графы**, специально сгенерированные на языке Python для поиска точных границ применимости (графы серий `probe_*` и `wiki_*` с контролируемой плотностью и шириной фронта).

## Верификация и тестирование

Корректность реализаций проверяется с помощью набора модульных тестов (файлы `src/tests/`). Тестирование разделено на три сценария:

1. **Тестирование на связных графах:** Проверяется, что обе реализации обходят все вершины, корректно вычисляют уровни (расстояния) и строят дерево предков без циклов.
2. **Тестирование на несвязных графах:** Проверяется, что алгоритмы корректно находят компоненту связности источника, а недостижимые вершины остаются с уровнем `-1`.
3. **Сравнение с эталоном (BGL):** Написан отдельный тест (`test_comparison.cpp`), который прогоняет одинаковые графы через классический C-код, GraphBLAS и библиотеку Boost Graph Library. Тесты подтверждают, что все три реализации строят идентичные структуры предков и посещают ровно те же вершины.

## Сравнение производительности с BGL

Помимо проверки корректности, было проведено детальное сравнение скорости разработанного классического BFS на чистом C с эталонной библиотекой BGL.

Результаты замеров показали, что **собственная реализация на C стабильно обгоняет BGL в диапазоне от 1.18 до 2.70 раз**. 
Максимальный отрыв зафиксирован на графах:
*   `probe_n1200k_d4.5_wide.mtx`: код на C быстрее в **2.70 раза** (93 943 мкс против 254 030 мкс).
*   `cit-Patents.mtx`: код на C быстрее в **2.40 раза** (2 878 мкс против 6 917 мкс).

**Почему C-код быстрее BGL?**
*   **Гибкость против скорости:** BGL — это универсальная шаблонная библиотека C++. Она поддерживает любые типы графов и свойств, что создает накладные расходы (динамические итераторы, `property maps`).
*   **Событийная модель (Visitors):** Для построения дерева предков BGL использует механизм «посетителей», проверяющий условия на каждом шаге.
*   **Специализация:** Наша реализация написана на C под конкретную CSR-структуру и лишена оверхеда на абстракции.

*Единственное исключение:* сверхплотные синтетические графы серии `probe_n4000k_d40.0`, где внутренние оптимизации кэширования BGL дали ей преимущество в 1.17 раза. Полная таблица со сравнением всех графов находится в файле bfs_bgl_comparison_table.pdf.

## Главный результат: Граница применимости

В ходе работы на основе замеров на 54 графах (реальных из SuiteSparse и синтетических) была выведена **трехступенчатая эмпирическая граница**. 

Библиотека **GraphBLAS работает быстрее**, если выполняется *хотя бы одно* из следующих условий:
*   **Очень плотные графы:** средняя степень вершины `>= 31` при ширине фронта `> 60 000`.
*   **Средняя плотность графа:** средняя степень вершины `>= 4.4` при ширине фронта `> 290 000`.
*   **Экстремально широкие фронты:** средняя степень вершины `>= 1.4` при ширине фронта `> 600 000`.

Во всех остальных случаях (разреженные графы с узким фронтом) **классический BFS на C оказывается быстрее**. 
Точность данной модели на тестовой выборке составила **100%**.

Полная диаграмма границы применимости находится в файле **bfs_applicability_boundary.pdf**.

## Требования и зависимости

Для сборки проекта необходимы:
*   Компилятор с поддержкой C11 и C++17 (GCC или Clang).
*   Система сборки `CMake` (версия 3.10+).
*   Библиотека `Boost` (заголовочные файлы).
*   **`SuiteSparse:GraphBLAS` версии 10.5.1** (Более старые версии, например 7.x из репозиториев Linux, не поддерживаются из-за отличий в API).

### Установка зависимостей (Ubuntu/Debian)

```bash
sudo apt update
sudo apt install cmake libboost-all-dev g++ make
```

**Установка GraphBLAS 10.5.1 из исходников:**
```bash
wget https://github.com/DrTimothyAldenDavis/GraphBLAS/archive/refs/tags/v10.5.1.tar.gz
tar -xzf v10.5.1.tar.gz
cd GraphBLAS-10.5.1
mkdir build && cd build
cmake --build .
sudo make install
sudo ldconfig
```

## Сборка проекта

```bash
# Клонируйте репозиторий (используется Git LFS для графов)
git clone https://github.com/MariaPentegova/graph_blas_bfs-2.git
cd graph_blas_bfs-2

# Создайте папку для сборки и скомпилируйте
mkdir build
cd build
cmake --build .
```

После успешной сборки в папке `build` появятся исполняемые файлы `bfs_analysis`, `bfs_benchmark` и тесты.

## Использование

### 1. Анализ конкретного графа (Утилита `bfs_analysis`)
Программа автоматически запускает обход от вершины с максимальной степенью, вычисляет метрики и выдает рекомендацию (Classic BFS или GraphBLAS).

```bash
./bfs_analysis ../graphs/название_графа.mtx
```

Вы также можете указать конкретную стартовую вершину (например, вершину с индексом 42):
```bash
./bfs_analysis ../graphs/название_графа.mtx 42
```

**Пример вывода:**
```text
>>> RECOMMENDATION: GraphBLAS
       Reason: avg_degree >= 4.4 AND max_width > 290k
```

### 2. Запуск полного бенчмарка
Для запуска всех графов из папки `graphs` и записи результатов в CSV:
```bash
./bfs_benchmark
```
*(Результаты сохраняются в файл `benchmark_results.csv`).*

## Тестирование (Верификация)
Корректность реализаций проверяется с помощью модульных тестов. Проверяется совпадение деревьев предков с эталонной BGL, а также работа с несвязными графами.

```bash
# Запуск всех тестов
ctest

# Или запуск конкретных тестов
./test_classic_bfs
./test_comparison
./test_graphblas_bfs
```
